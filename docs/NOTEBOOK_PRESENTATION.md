# Notebook presentation view

Every code cell in the active workshop notebooks has a descriptive Markdown subheading
immediately above it, such as **Generate frozen MoLFormer embeddings**. The heading is
followed by one concise, plain-text paragraph beginning with "Code Summary: " that explains
what the following code does in context, without presenter instructions or bullet lists.
The heading names the main action, and the explanation summarizes its purpose so readers
can follow the workflow without reading the code.
They also cover the worked examples, installation check, prompt template, and instructor
feature study. Intentionally blank practice cells remain blank. Markdown-only notebooks
need no changes. Archived notebooks and generated output copies are excluded.

## Notebook numbering

Use the filename prefix, not a separately numbered list, to identify a notebook.
The [BP sequence](../01_boiling_point/README.md) is `00` acquisition, `01` ten-step
template, and `02` prompt-driven workbook. Acquisition is pre-work; the live exercise
uses 01 as a template and asks an assistant to populate 02. Its
[examples](../01_boiling_point/examples/README.md) hold four optional notebook references,
numbered separately `01`–`04`, plus the two one-shot prompt text files. The
[IR](../02_ir_functional_groups/README.md) sequence runs `00`–`02`, with a prompt-only
01 workbook and a static 02 trainer. Its completed 01, alternatives 01a–01d and 03
comparison are [optional references](../02_ir_functional_groups/examples/README.md).
[HTEM](../03_htem_conductivity/README.md) also runs `00`–`02`: completed preparation
in 01 and a prompt-only model-development workbook in 02. Its completed 02, alternatives
02a–02d and 03 comparison are [optional references](../03_htem_conductivity/examples/README.md).
Lettered examples are alternatives to an existing step.
First-cell titles must match the filename prefix. See the
[workshop roadmap](../00_Workshop_Roadmap.ipynb) for the participant path.

## Read explanations and outputs; expand code when needed

In **VS Code**, with the notebook editor active:

1. Open the Command Palette: `Ctrl+Shift+P` on Windows/Linux or `Cmd+Shift+P` on macOS.
2. Search **Collapse All Cell Inputs** and run the notebook command.
3. Leave cell outputs expanded. Read the summaries and existing figures/tables in order.
4. To edit, expand an individual input or run **Expand All Cell Inputs**.

VS Code stores editor view state, so previously opened notebooks may need this command
even after pulling the updated files. Reopen the notebook if an already-open editor has
not picked up new Markdown cells. Do not use a command that collapses outputs.

For **JupyterLab**, code cells have `metadata.jupyter.source_hidden: true` and
`outputs_hidden: false`; expand inputs using the left-hand cell collapser or the View
menu. Legacy `collapsed` metadata is false because that flag can hide outputs.
These are [standard notebook metadata fields](https://nbformat.readthedocs.io/en/latest/format_description.html#cell-metadata).
See also [JupyterLab's notebook controls](https://jupyterlab.readthedocs.io/en/stable/user/notebook.html)
and [VS Code's notebook guide](https://code.visualstudio.com/docs/datascience/jupyter-notebooks).

This is a display choice, not a security measure. Code remains in the file, can be run
normally, and may remain visible in GitHub or other static renderers. Outputs are existing
saved results, not regenerated by this presentation update. A hidden input is still
executed by Run All. Check acquisition flags before running a download notebook.

## Maintaining the summaries

For a searchable browser version with code folded and saved results visible, use the
[Quarto reading website](QUARTO_WEBSITE.md). It renders the existing notebooks without
executing them; the VS Code/JupyterLab instructions above still apply to coding sessions.

Curated headings and summaries live in `scripts/prepare_notebook_presentation.py`, in the
`HEADINGS` and `NOTES` catalogs, in code-cell order for each notebook. Update the matching
heading and paragraph whenever the code changes. After rebuilding
notebooks using any instructor generator, reapply the presentation layer:

```bash
uv run --locked python scripts/prepare_notebook_presentation.py
uv run --locked python scripts/prepare_notebook_presentation.py --check
uv run --locked python scripts/ci/validate_notebooks.py
uv run --locked python -m unittest discover -s tests -q
```

The preparation command is idempotent and does not execute notebooks. It preserves
original code, outputs, execution counts, IDs, images, captions, and unrelated metadata;
it adds only explanatory Markdown and input/output visibility settings. A missing or
wrong-sized summary catalog fails before any notebook is rewritten. Generated summaries carry
the associated code's checksum, so `--check` and the tests flag edits needing a refresh.
Checksums detect source drift, not whether an explanation is scientifically correct:
review the summaries before reapplying them to changed code. Automated tests also verify
coverage, descriptive headings with correctly prefixed concise paragraphs, preserved
computation, visibility flags, and idempotence.
