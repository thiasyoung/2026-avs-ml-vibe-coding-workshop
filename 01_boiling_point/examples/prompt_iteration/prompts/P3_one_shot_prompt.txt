3. ASK: WHAT TO DO
======================================================================

Work in the order below. Each phase names the reasoning strategy it practices so participants can recognize it.

PHASE A - Plan-and-Solve (plan before code)
Before writing the notebook, write a short numbered plan (10-20 lines) covering: data source, cleaning and identity rules, split design, feature sets, baseline and candidate models, experiments, creative enhancement, optimization, final evaluation, and inference. Note your main risks, such as leakage, duplicate molecules, unit errors, and runtime, and say how you will guard against each. Then proceed without waiting for approval. Put a condensed version of this plan in the notebook under Step 0.

PHASE B - Least-to-most (build from the smallest working piece)
Break the problem into subproblems and solve them in increasing order of difficulty. Execute each stage before you build on it:
  1. Load data and parse SMILES -> working table.
  2. Clean, canonicalize, de-duplicate -> eligible molecules.
  3. Frozen molecule-disjoint splits -> saved assignments.
  4. Training-median baseline -> first validation MAE.
  5. One simple featurized model -> first real comparison.
  6. Richer features, models, and the creative enhancement.
  7. Optimization, freeze, then final test and inference.
Do not write all the code at once and hope it runs. Prompt -> run -> check -> improve at every stage.

PHASE C - Zero-shot chain-of-thought (reason through each decision)
For every substantive decision in Steps 4-10, think it through step by step before choosing: What are the options? What does chemistry suggest? What does ML best practice require? What does the data show? Then summarize that reasoning in a short "Decision" markdown cell in the notebook. Show the conclusion and key reasons, not a long derivation.

Few-shot chain-of-thought example: use this style for Decision cells.

  EXAMPLE 1 (data carpentry):
  **Decision: how to handle repeated measurements of the same molecule.**
  Options: keep all rows, keep the first row, or aggregate per molecule.
  Reasoning: (1) Repeated rows of one canonical structure are one molecule, so splitting them across train and test would leak the answer. (2) Repeated values that agree within a few kelvin are probably independent reports of the same property; the median is robust to one bad report. (3) Values that disagree by more than a set tolerance (choose and justify one, e.g. 10 K) may come from different pressures or data errors, so averaging them would hide a problem.
  Choice: aggregate agreeing repeats to the median; flag conflicting groups in the audit and exclude them; report counts.
  What the learner should notice: identity is decided before splitting, not after.

  EXAMPLE 2 (feature engineering):
  **Decision: whether to add hydrogen-bond donor and acceptor counts.**
  Reasoning: (1) Ethanol (46 g/mol, BP about 351 K) boils far above propane (44 g/mol, BP about 231 K) despite nearly equal mass, so mass alone misses intermolecular hydrogen bonding. (2) RDKit can count donors and acceptors from SMILES alone, so the feature is available at inference. (3) Hypothesis: adding these counts lowers validation error most for alcohols, acids, and amines.
  Test: compare validation MAE with and without the counts, overall and for the H-bonding subgroup.
  What the learner should notice: a chemical idea becomes a testable, controlled experiment.

Do not copy these choices blindly; check the actual data and adjust them.

PHASE D - Steps 4-10 (the core work)

Step 4 - Examine Data
- Load and preview the selected file. Audit schema, missing or nonnumeric BP, nonfinite values, empty or unparseable SMILES, salts and multi-component entries, charges, isotopes, stereochemistry, duplicate rows, and different SMILES that canonicalize to the same structure.
- Report counts and representative flagged rows with reasons. An unusual value is a reason to inspect, not automatically an error.
- Establish units from provenance, not from the range of values alone.
- After only the minimal validity and identity checks, reserve the splits (see Step 5) BEFORE target-informed exploration. Then make one or two readable training-only figures, such as a BP distribution and BP versus a simple size descriptor, with units and sample counts.

Step 5 - Data Carpentry
- Apply a conservative, documented cleaning policy. Save a row-level audit with original SMILES, canonical SMILES, action, and reason. Never overwrite source data.
- Define a canonical molecular identity, for example canonical SMILES of the standardized parent, or InChIKey. Keep each identity in one split. Decide how stereoisomers are treated and state it.
- Freeze an 80/10/10 train/validation/test split of unique molecules (seed 42) unless you can justify a better design. A scaffold or cluster-grouped split is welcome if justified, but handle acyclic molecules sensibly. Explain what the split estimates and where it is weak, such as unfamiliar chemical families. Save the assignments and assert that identities are disjoint across splits.
- Build at least two representations derived only from SMILES:
    (i) a compact, interpretable descriptor set motivated by the chemistry in ROLE (size, polarizability proxies, branching or shape, polarity, H-bonding, aromaticity, halogens, functional groups), and
    (ii) a structural representation such as Morgan count fingerprints or fragment counts.
  Fit scaling, imputation, and feature selection only on training data, inside reusable pipelines.

Step 6 - Algorithm
- Define a training-median dummy baseline first.
- Choose 2-3 complementary regression candidates suited to roughly a few thousand molecules and these representations, for example a regularized linear model as an interpretable reference, a tree ensemble or gradient boosting model, and optionally a kernel or small neural model. Justify each choice in one or two sentences, including expected strengths and weaknesses.
- Give every candidate the same build/fit/predict interface so training and inference apply identical transformations. Do not invent epoch histories for non-iterative models. For iterative models, use validation-based early stopping and restore the best checkpoint.

Step 7 - Experiment
- Create a small experiment tracker: numbered experiment folders, metadata.json (hypothesis, features, model, settings, seed, runtime), train/validation predictions.csv, training_history.csv when applicable, and a running experiment_summary.csv.
- Run a bounded set of fair experiments on the frozen train/validation partitions: model-family comparison, at least one controlled feature ablation, and a modest settings search.
- CREATIVE ENHANCEMENT (required). Propose 3 chemically and statistically motivated ideas that could make predictions more accurate or more useful. Rate each for expected benefit, cost, and risk, and choose 1-2 to implement and evaluate against a simpler control. Possible directions (suggestions, not a checklist):
    * a physics-informed prior plus learned residual, e.g. a simple size or group-contribution trend that a model corrects;
    * combining interpretable descriptors with fingerprints, then checking which helps which chemical classes;
    * an applicability-domain score, such as nearest-neighbor Tanimoto similarity to the training set, shown to relate to validation error;
    * nearest-training-molecule explanations shown beside each prediction;
    * a small model ensemble whose spread is checked against validation error;
    * a graph neural network (Chemprop is installed) only if it fits the runtime budget.
  Define in advance what counts as "helped", and report the result honestly, even if the idea did not help.
- If you report prediction intervals, calibrate them on data kept separate from model selection, state the assumptions, and later report empirical coverage and width. Do not call similarity or ensemble spread a calibrated probability.
- Produce a readable validation-comparison figure. Do not compute or look at test predictions in this step.

Step 8 - Analysis
- Rank experiments by validation MAE (kelvin). Inspect the train/validation gap, validation parity and residual plots, and error by chemical subgroup (e.g. H-bond donors present or absent, aromatic, halogenated, size bins), with counts so small groups are not over-interpreted.
- Show 3-5 representative chemical successes and failures and explain them chemically as hypotheses.
- Describe feature importances as associations, not causes.
- Keep the test set sealed here because Step 9 can still change the model. Explain this refinement of the template briefly.

Step 9 - Optimization
- Make one focused, affordable improvement motivated by Step 8. Change one main factor so the effect can be understood. Compare it with the current best using the same validation procedure, and keep the simpler model if the gain is negligible. Do not search until a desired score appears.
- Freeze the full pipeline (cleaning policy, features, model, settings, applicability rule, any calibration) and record the frozen configuration before opening the test set.

Step 10 - Solved?
- Evaluate the frozen model and the dummy baseline on the test set once. Report train, validation, and test counts plus MAE and RMSE (K) and R^2. Include test parity and residual plots and a few representative errors. Do not tune after seeing test results.
- Answer the Step 1 success criterion with actual numbers. If the model did not beat the baseline, explain why; do not change the split or rerun until the result looks good.
- Provide `predict_boiling_point(smiles)` that accepts one SMILES or a list, preserves input order, and returns a table with input SMILES, canonical SMILES, predicted BP (K, plus C), status (ok / invalid / unsupported), applicability score or flag, and the nearest training molecule. Reject invalid or unsupported inputs explicitly instead of returning a misleading number.
- Save the complete inference pipeline. Verify that a fresh Python process can reload it and reproduce predictions without retraining.
- Demonstrate several chemically contrasting molecules, such as a small alcohol, a branched alkane and its linear isomer, an aromatic, and a halocarbon, plus an invalid string. Mark any demo molecule that is already in the training data; it is not independent evidence.
